# FDE

| FDE開発ライフサイクル | クライアント / AIエージェント層 | MCPサーバー層| インフラストラクチャ層 | セキュリティ層 |
| --- | --- | --- | --- | --- |
| **1. 要件定義・スコープ策定**<br><br><br>(Discovery & Scoping) | 利用するAIクライアントや自社UIの選定、エージェントの推論要件の定義<br><br>（**Amazon Bedrock Agents**, カスタムUI用 **ECS / Amplify**） | 連携対象となる社内システム（DB、SaaS、API）の仕様・要件分析<br><br>（軽量: **Bedrock Action Groups**, 重厚: コンテナベースの設計） | 閉域網・オンプレ・クラウドといったインフラ環境要件、ネットワーク設計<br><br>（**Amazon VPC**, **AWS Direct Connect**, **Transit Gateway**） | 複数バックエンドの集約・ルーティング設計、認証・認可境界、機密情報要件の定義<br><br>（**AWS IAM**, **AWS Secrets Manager**, **AWS PrivateLink**） |
| **2. プロトタイピング & 検証**<br><br><br>(Prototyping & Validation) | 開発者によるプロンプトの挙動テストやオーケストレーションの動作確認<br><br>（**Bedrock Console**, ローカルのClaude Desktop） | 個別システムにアクセスする最小限のモックやAPIラッパーの実装と単体テスト<br><br>（**AWS Lambda**, コンテナ検証用 **Amazon EC2 / AWS Cloud9**） | ローカル環境や開発用VMを利用した即時検証の開始<br><br>（ローカルK8s/Docker, **Amazon EC2**） | 簡易的な疎通テスト、テスト用のNGワード設定・入力バリデーション確認<br><br>（**Bedrock Guardrails Test**, ローカルプロキシの動作確認） |
| **3. ゲートウェイ・ブリッジ開発**<br><br><br>(Gateway & Bridge Development) | クライアント側から見た接続先の抽象化・単一化のインターフェース設計<br><br>（**Amazon Bedrock Agents API**） | 各バックエンドごとの固有ロジック、エラーハンドリング、OpenAPIスキーマの整形<br><br>（軽量: **AWS Lambda**, 常駐・重負荷: **Amazon EKS / AWS Fargate**） | IaCを用いたリソース（コンテナ基盤含む）の定義とパイプライン作成<br><br>（**AWS CDK**, **Amazon ECR**, **Amazon EKS / ECS**） | 複数ターゲットの集約・ルーティング、入力ガードレール、ポリシー制御の実装<br><br>（**Amazon Bedrock Guardrails**, Ingress防御の **AWS WAF**, **API Gateway**） |
| **4. 本番インテグレーション**<br><br><br>(Production Hardening) | 検証用環境から、本番用の自社製WebアプリやカスタムUIへの統合<br><br>（**AWS SDK**, トラフィック制御の **ALB**） | バックエンド障害に対するレジリエンス強化、同時実行数の制御<br><br>（**Amazon EKS HPA**, **ECS Auto Scaling**, **AWS Step Functions**） | コンテナ/サーバーレス混在環境への本番デプロイ、ロードバランシングと高可用性の担保<br><br>（**Amazon EKS / ECS**, **Elastic Load Balancing (ALB/NLB)**） | Pod/タスク単位の安全な権限伝搬、監査ログの有効化、実運用ポリシーの適用<br><br>（**AWS IAM Roles for Service Accounts (IRSA)**, **AWS CloudTrail**） |
| **5. 運用・拡張**<br><br><br>(Operation & Evolution) | 新しい基盤モデルへの切り替え、プロンプトの継続的なチューニング<br><br>（**Amazon Bedrock**） | 追加される社内システムやAPI変更に伴うアダプターロジックのメンテナンス・拡張<br><br>（**Lambda** の更新, **EKS / ECS** 上のコンテナローリングアップデート） | コンテナ及びマネージドリソースのメトリクス監視、ログの集約、リソース最適化<br><br>（**Amazon CloudWatch Container Insights**, **AWS Compute Optimizer**） | 新規追加ツールの動的ルーティング管理、分散トレーシング、脅威検知の継続監視<br><br>（**AWS Security Hub**, **AWS X-Ray**, **Amazon GuardDuty**） |
